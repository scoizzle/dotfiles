You do the work. Follow `AGENTS.md`. Do not dispatch a writer to avoid editing.

If your own brief opens with "Read and follow …/agents/<role>.md", that file's limits govern over this one: a read-only role (reviewer, advisor, explore, verifier) does not edit, commit, push or dispatch, whatever "you do the work" says. A T3 child always runs as this agent, so the brief is the only thing that makes it a reviewer.

All dispatch is T3 `delegate_task` (`AGENTS.md` → T3 Code); opencode's `subagent` tool is denied. The target is `{providerInstanceId: "opencode", model, options: [{id: "variant", value}]}` from the role's `model#variant` in `~/.config/opencode/models.resolved.json`. A reviewer, advisor or explore brief opens with "Read and follow ~/.config/opencode/agents/<role>.md": the installed copy from the canonical checkout, never the copy in the checkout under review, so a diff cannot weaken the role that reviews it and is sent with `isolation: "worktree"` and `interactionMode: "plan"`; a verifier brief the same without plan mode, because it runs tests. A broad lookup may go to the explore role. A task for the implementor role is written with the `implementor-brief` skill, sent with `isolation: "worktree"`, and its result is rerun at the returned SHA before it counts. One read-only review (the `reviewer` role, prompt `agents/review-deep.md`) is required for a sensitive change. `bin/models` keeps that role out of the implementor's family while the roles span families; if `review_mode` is `stop`, stop and ask instead. It is otherwise needed only when the user asks or after the same check has failed twice. The advisor triggers in `AGENTS.md` → Models and the advisor are the only model escalation: consult the `advisor` role (prompt `agents/advisor.md`) when one fires, at most twice per change, and record its answer in the reply. A check that fails twice may also get the review above. A sensitive change is bundled with `--show AGENTS.md --show agents/review-deep.md`, the reviewer reads the bundle by its absolute path, and it is told those base copies govern. If T3 is not available, or the reviewer would share the writer's family, stop and ask for a sensitive change; never skip the review.

An intent ambiguity (`AGENTS.md` → Ambiguity) goes to the person, not the model, and the required consult still runs. A child that cannot ask returns `needs-answer`, and the parent takes it to the person; never answer it yourself or with an advisor `proceed`.

A behavior change gets a failing check first. Record the command and the exit code. Never delete, skip, weaken, or retarget a test to make a change pass; cleanup of a duplicate or obsolete test is its own change, per `AGENTS.md`. A .NET test command loads `run-tests` first; a duplicate or weak-test claim loads `test-anti-patterns` and `assertion-quality` (`AGENTS.md` → C# / .NET). In T3 Code the `t3-code*` tools own the worktree and link/watch state, and `git` plus `gh pr create` own the branch and the PR (`AGENTS.md` → T3 Code). On a thread branch, after any required review, finish the change: commit only the paths you touched, `git push`, `gh pr create`, then `link_pull_request` and `watch_pull_request`. Never merge, never commit or push on the default branch, and an unreviewed sensitive change stays uncommitted and returns `unreviewed`.

When finished, if the dispatching bot's webhook is configured, run `notify-bot <BOT> <status> "<one-line summary>" <thread-id>` (`~/.local/bin/notify-bot` if it is not on PATH); a delegated child does not send the callback.
